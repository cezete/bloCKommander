## Transport contract

WorkingCopyTransportContext holds Hall, Program and WorkingCopy UUIDs. Hall DTOs
must supply all three before registry installation or world rendering.
Scoped successful HTTP responses must confirm mode=explicit,
content_scope=SHARED_PROGRAM and the exact request identities. Stage-scoped
responses must additionally confirm the requested Stage. Missing, malformed or
foreign context produces a protocol failure before the success callback.
Error responses retain their existing structured API contract.

| Operation | Identity source | Transport |
|---|---|---|
| Block create/update/delete | Physical Hall at interaction; form retains Hall and Stage IDs | Explicit headers; Stage response checked |
| Graph GET, Wire place/layout, bind, reconciliation | Captured WireStageContext from initiating Hall | Explicit headers; context and Stage checked |
| Mounted Program and SAVE sign status | Hall registry mount | Explicit headers; context checked |
| Child ensure and Stage navigation GET | Captured initiating Hall mount | Explicit headers; context and Stage checked |
| SAVE button | Control's Hall, active Stage fence | Explicit headers; context and Stage checked |
| Hall creation | No mount exists before response | Legacy; returned Hall requires complete identity |
| World Hall list and restore | Per-Hall identities in returned list | Legacy bootstrap; subsequent Graph/Program calls explicit |
| Destroy button | Control coordinates | Legacy: Python A1.2 rejects explicit context on this route |

There is no Stage-ID-based Hall lookup in the active interaction transport.
Opening a block form captures Hall/Stage/block identity; submission checks the
same Hall's current Stage. Navigation carries the initiating mount through child
creation, target Stage reads and Graph reads. Reconnect passes the actual Hall to
Graph reconciliation and retains that Hall ID for SAVE state completion.

## Gate 2 work still required

GraphProjectionStore slots and WireInteractionCoordinator world state are still
Stage-keyed. They must become keyed by Hall/mount identity plus Stage before the
complete A1.3 can be accepted for shared-Program multi-Hall world projection.
Registry projection accesses, lifecycle tokens, world projection fences and
navigation target slots must adopt the same key. Removing/reinstalling a slot
must never make an earlier request token valid again.

The existing shared Program workspace, atomic Program SAVE, graph command
payload, epoch/revision and request-id contracts remain unchanged.
Python legacy mode has not been disabled.
