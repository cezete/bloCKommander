# CK-07/A1.2 – Python transport context

Identity validation only. ProgramWorkspace and StageWorkspace, Program-SAVE and
dirty state still describe the shared Program. There is no content isolation.

## Explicit requests

Send all three UUID headers, on existing URLs and with unchanged domain payloads:

- `X-BlockCommander-Hall-Id`
- `X-BlockCommander-Program-Id`
- `X-BlockCommander-Working-Copy-Id`

The common HTTP preflight resolves the live database mount with the A1.1
repository resolver. URL/control Hall and Program identities must agree. Stage
membership is read from PostgreSQL; new, unsaved Stage identity may be read from
an already existing Program workspace without loading or installing one.
Existing endpoint authentication and domain owner checks remain in force.

Context fields in request bodies or query parameters are rejected on the scoped
routes: they must not be silently interpreted as a legacy request. Partial or
malformed identity headers are never downgraded to legacy mode.

Successful scoped responses add `transport_context`, containing `mode`,
`program_id`, optional `stage_id`, verified `hall_id` / `working_copy_id` where
available, and `content_scope: SHARED_PROGRAM`. Graph domain DTOs, schema version,
CAS, revision, epoch and domain request-idempotency keys are unchanged.

## Transitional legacy rules

- Default: `BLOCKCOMMANDER_ALLOW_LEGACY_CONTEXT=1`.
- Stage/Program-scoped requests without identity headers may run only when the
  Program has at most one persisted Hall mount. They are marked `legacy_program`;
  no caller Hall or WorkingCopy is inferred, even with a single mount.
- Zero-mount Programs retain their previous Program-domain access. This is not
  authorization to project a world or to access a particular WorkingCopy.
- With multiple Hall mounts, these unscoped reads and mutations return 409
  `CONTEXT_REQUIRED` before entering the domain service.
- A Hall URL, rebuild code resolved through the repository, or SAVE control
  coordinates identify a Hall without guessing. Such legacy requests validate
  that Hall's live mount and are marked `legacy_hall`. SAVE still saves the
  entire shared Program, including changes originating in another Hall.
- Bulk world reads and restore preflight every known Hall mount before the
  existing handler runs. Their Hall DTOs carry the A1.1 identity fields.
- A single explicit context cannot scope a bulk operation, creation of a new
  Hall, or unrelated routes: return 409 `CONTEXT_ROUTE_UNSUPPORTED` before work.
- Set `BLOCKCOMMANDER_ALLOW_LEGACY_CONTEXT=0` to disable the compatibility adapter
  on scoped routes. Explicit headers then remain mandatory; there is no second
  Stage-based or singleton-mount fallback.

Validation errors use the endpoint's Graph or Program API version and include
`status`, `error_code`, `message`, and `diagnostics`. Codes: `INVALID_CONTEXT_ID`,
`INCOMPLETE_CONTEXT`, `CONTEXT_LOCATION_INVALID` (400), `HALL_NOT_FOUND`,
`MOUNT_NOT_FOUND` (404), `HALL_PROGRAM_MISMATCH`,
`WORKING_COPY_PROGRAM_MISMATCH`, `FOREIGN_WORKING_COPY`,
`CONTEXT_MISMATCH`, `STAGE_PROGRAM_MISMATCH`, `CONTEXT_REQUIRED`, and
`CONTEXT_ROUTE_UNSUPPORTED` (409).
Repository connection/query failures return `CONTEXT_REPOSITORY_UNAVAILABLE`
(503), without exposing database details or entering a domain operation.

## Legacy compatibility matrix

| Route group | Explicit context | Legacy request | Multiple Halls on one Program | Invalid context | A1.3 dependency |
|---|---|---|---|---|---|
| Stage block create/update/delete, Stage save/rebuild | Supported; all three headers and Stage membership are checked | Supported only for an unambiguous Program with at most one mount | Legacy is rejected with `CONTEXT_REQUIRED`; explicit remains shared-Program scoped | Structured identity or Stage mismatch before domain mutation | Fabric must send the three headers |
| Graph GET, `WIRE_LAYOUT`, `WIRE_PLACE_INTENT`, `BIND_EDGES` | Supported after graph transport authentication | Supported only for an unambiguous Program with at most one mount | Legacy is rejected; explicit keeps existing epoch/revision and idempotency semantics | Structured context error before graph application/idempotency insertion | Hall-aware projection and request transport remain A1.3 work |
| Program GET, Stage/child navigation, child ensure, dirty/status, Program SAVE | Supported; URL Program/Stage must match the live mount | Supported only for an unambiguous Program with at most one mount | Legacy is rejected; explicit SAVE still saves the complete shared Program | Structured context error before workspace load or SAVE | Fabric navigation/status/SAVE must carry identity |
| Mounted Program by Hall URL, Hall rebuild, rebuild by code | Supported when the header Hall matches the route-resolved Hall | Supported as `legacy_hall`; the URL/code identifies the Hall without guessing | Supported because the Hall is independently identified | Hall/mount/identity mismatch | A1.3 should make the explicit contract universal |
| SAVE button | Supported when headers match the control-coordinate Hall and active Stage | Supported as `legacy_hall`; control coordinates identify the Hall | Supported; SAVE remains Program-wide | Context mismatch before Program SAVE | Fabric SAVE should carry explicit identity |
| World Hall list and Hall restore/reconnect | A single context is rejected with `CONTEXT_ROUTE_UNSUPPORTED` | Supported after every returned/candidate Hall mount is validated | Each known Hall is validated independently | Missing Hall mount aborts before restore mutation | A1.3 needs a per-Hall bulk/reconnect context contract |

No compatibility path selects the first Hall by Stage or Program identity, and
no response claims WorkingCopy content isolation.

## A1.3 dependencies

The existing Fabric remains usable in its unambiguous, single-mount workflows.
Multiple Hall mounts of the same Program require explicit headers for Stage,
Graph, child and Program requests; the old Fabric does not send these and gets
`CONTEXT_REQUIRED`. This is a deliberate safe refusal, not an arbitrary Hall
selection. Hall-bound SAVE may still succeed with shared Program semantics.

A1.3 must carry identity through Graph/Wire projection keys, request tokens and
Hall selection. Python context validation alone does not fix Fabric's shared
Stage-ID projection slots. Bulk reconnect needs an explicit per-Hall transport
contract before legacy mode can be disabled for an A1.3 deployment.

Mounts are validated at request entry. This is not a transactional mount lease;
no remount API, mount-generation protocol or new concurrency model is added.
